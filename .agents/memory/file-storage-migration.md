---
name: File storage migration
description: Ограничения совместимости файлового хранилища и порядок восстановления пути
---

Файловые маршруты должны сначала читать текущий каталог, затем поддерживать все исторические inline-форматы и лениво переносить найденные данные в файловое хранилище.

**Why:** При переходе с base64 в PostgreSQL на bind-mounted каталог старые записи могут иметь разные форматы, а асинхронное восстановление каталога позволяет ранней загрузке попасть не туда.

**How to apply:** Восстанавливать сохранённый путь до регистрации маршрутов и при чтении проверять legacy-поля; записи без байтов ни на диске, ни в БД требуют повторной загрузки.
